၁.၁ ဒီ project က ဘာလဲ
--------------------------------------------------------------------------------
DeepSeek-V3 ဆိုတာ DeepSeek-AI ကုမ္ပဏီက ထုတ်ထားတဲ့ Large Language Model (LLM)
တစ်ခုပါ။ ChatGPT လို စာသားတွေကို နားလည်ပြီး စာသားအသစ် ထုတ်ပေးနိုင်တဲ့ AI
မော်ဒယ်ပါ။

ဒီ repository ထဲမှာ training code မပါပါဘူး။ ပါတာက:
  - နည်းပညာစာတမ်း (DeepSeek_V3.pdf)
  - မော်ဒယ်ကို run ဖို့ (inference) ရေးထားတဲ့ ရိုးရှင်းတဲ့ reference code
    (စုစုပေါင်း Python ~၁၄၀၀ လိုင်းခန့်)

Model weights (လေ့ကျင့်ပြီးသား parameter တွေ) ကိုတော့ HuggingFace ကနေ
သီးသန့် download လုပ်ရပါတယ်။

၁.၃ အဓိက နည်းပညာ ၃ ခု
--------------------------------------------------------------------------------
(က) Mixture-of-Experts (MoE)
  - Layer တစ်ခုစီမှာ Expert (သေးငယ်တဲ့ neural network) ၂၅၆ ခု ရှိပါတယ်။
  - Token တစ်ခုဝင်လာတိုင်း Gate က အသင့်တော်ဆုံး Expert ၈ ခုကိုပဲ ရွေးပြီး
    အလုပ်လုပ်ခိုင်းပါတယ်။ ဒါ့အပြင် အမြဲတမ်းသုံးတဲ့ shared expert ၁ ခုလည်း
    ရှိပါတယ်။
  - ဒါကြောင့် မော်ဒယ်က ကြီးပေမယ့် တွက်ချက်ရတာ သက်သာပါတယ်။ ဆေးရုံကြီးမှာ
    ဆရာဝန် ၂၅၆ ယောက်ရှိပေမယ့် လူနာတစ်ယောက်ကို သက်ဆိုင်ရာ ဆရာဝန် ၈ ယောက်ပဲ
    ကြည့်ပေးတာနဲ့ တူပါတယ်။
  - Code: inference/model.py:532 (Gate), inference/model.py:633 (MoE)

(ခ) Multi-head Latent Attention (MLA)
  - ပုံမှန် attention မှာ Key/Value cache က memory အများကြီး စားပါတယ်။
  - MLA က KV ကို rank 512 ရှိတဲ့ low-rank vector သေးသေးလေးအဖြစ် ချုံ့ပြီး
    သိမ်းပါတယ်။ ဒါကြောင့် စာရှည်ရှည် (128K) ကို memory နည်းနည်းနဲ့
    ကိုင်တွယ်နိုင်ပါတယ်။
  - Code: inference/model.py:393 (MLA)

(ဂ) FP8 Precision
  - Weight တွေကို 8-bit floating point နဲ့ သိမ်းထားလို့ memory နဲ့ အမြန်နှုန်းမှာ
    အကျိုးရှိပါတယ်။
  - Block (128x128) တစ်ခုချင်းစီအတွက် scale factor သီးသန့် ထားပြီး တိကျမှု
    မကျအောင် လုပ်ထားပါတယ်။
  - Code: inference/kernel.py (Triton GPU kernel တွေ)

ဒါ့အပြင် Auxiliary-loss-free load balancing (Expert တွေကြား အလုပ်ကို loss
အပိုမသုံးဘဲ မျှဝေနည်း) နဲ့ Multi-Token Prediction (MTP) (token တစ်ခုထက်ပိုပြီး
ကြိုခန့်မှန်းနည်း) တို့ကိုလည်း သုံးထားပါတယ်။

၂.၀ အခြေခံ သဘောတရား
--------------------------------------------------------------------------------
FP8 (float8_e4m3fn) ဆိုတာ 8-bit ပဲသုံးတဲ့ ဂဏန်းပုံစံပါ။ ဖော်ပြနိုင်တဲ့
အကြီးဆုံးတန်ဖိုးက ±448 ပဲ ဖြစ်ပါတယ်။ ဒါကြောင့် ဂဏန်းတွေကို FP8 ထဲ မထည့်ခင်
scale (ချဲ့/ချုံ့ကိန်း) နဲ့ စားပြီး range ထဲ ဝင်အောင် လုပ်ရပါတယ်:

  quantize:    y = x / s        (FP8 အဖြစ် သိမ်း)
  dequantize:  x ≈ y * s        (မူလတန်ဖိုး ပြန်ရ)

Tensor တစ်ခုလုံးအတွက် scale တစ်ခုတည်း မသုံးဘဲ ဂဏန်း ၁၂၈ လုံးစီ (block)
အတွက် scale သီးသန့် ထားပါတယ်။ ဒါကို block-wise quantization လို့ ခေါ်ပါတယ်။
တန်ဖိုးကြီးတဲ့ ဂဏန်းတစ်လုံးကြောင့် တခြား ဂဏန်းသေးသေးလေးတွေရဲ့ တိကျမှု
မပျက်စေဖို့ပါ။

Triton ဆိုတာ GPU kernel တွေကို Python နဲ့ ရေးလို့ရတဲ့ language ပါ။
@triton.jit ပါတဲ့ function တွေက GPU ပေါ်မှာ program (thread block) အများကြီး
ပြိုင်တူ run ပါတယ်။ Program တစ်ခုစီက data အပိုင်းတစ်ပိုင်းစီကို
တာဝန်ယူပါတယ်။

ဖိုင်ထဲမှာ အပိုင်း ၃ ပိုင်း ရှိပြီး အပိုင်းတိုင်းမှာ GPU kernel (@triton.jit)
နဲ့ အဲဒါကို ခေါ်ပေးတဲ့ Python wrapper တစ်စုံစီ ပါပါတယ်။

၆.၄ apply_rotary_emb(): တကယ်လှည့်ခြင်း (Line 375-390)

[Complex number လှည့်ကွက်]

2D vector (a, b) ကို θ ထောင့် လှည့်ဖို့ ပုံမှန်ဆိုရင် rotation matrix လိုပါတယ်:
    [a']   [cos θ  −sin θ] [a]
    [b'] = [sin θ   cos θ] [b]
ဒါပေမယ့် (a, b) ကို complex number a + ib လို့ သဘောထားရင် e^(iθ) နဲ့
မြှောက်လိုက်ရုံနဲ့ လှည့်ပြီးသား ဖြစ်ပါတယ်:
    (a + ib) x (cos θ + i sin θ) = (a cos θ − b sin θ) + i(a sin θ + b cos θ)
ရလဒ် တူတူပဲ ဖြစ်ပြီး code ပိုရိုးရှင်းပါတယ်။
